# 01 · 需求分析

## 1. 背景

2026 年 9 月出现了一类新模型：**System-1 决策模型**。它们不生成文字，只对"状态 + 类型化问题"输出带概率的结构化答案：

| 原语 | 含义 | 返回 |
|---|---|---|
| `Choice` | 多选一 | 选中项 + 每个选项的概率 |
| `Score` | 在有序等级上打分 | 期望等级（可以落在两级之间）+ 各级概率 |
| `Noul` | 是 / 否判断 | P(true) |

代表模型有两个：

- **Jev**（TypeSafe AI，闭源 API，2026-09-15/19 发布，目前需排队申请）
- **Laya**（Convai Innovations，Apache-2.0 开源权重，可以在本机跑，接口与 Jev 兼容）

用户最初的设想（见 [02-任务判断](02-任务判断.md) 的逐条核实）是：量化交易需要"快、选择题、是非题、打分、不能瞎编、便宜"，这些正好对得上 Jev/Laya 的能力，所以两者"天然适合"。这个项目要把这个设想**做成能运行的系统，并用实验检验它**。

后来补充的需求：**把 Laya 和 Claude 结合起来**，最好能让 Laya 成为 Claude 的一部分。

## 2. 目标用户与场景

| 用户 | 想要什么 |
|---|---|
| 量化研究员 | 一个可以换模型的"判断层"，接进现有的因子、回测、风控流程，并能量化它到底有没有增量 |
| 用 Claude 做投研的人 | 让 Claude 能在几秒内批量筛几百条新闻或几十个标的，只把难的留给自己细看 |
| 技术评估者 | 在接入 Jev 或 Laya 之前，先知道它们在金融场景里的真实延迟、准确率、校准程度和失效方式 |

## 3. 功能需求

| 编号 | 需求 | 对应实现 |
|---|---|---|
| FR1 | 一套类型化问题定义（Choice / Score / Noul），可以原样发给 Laya、Jev、Claude | `typed.py`（与 Jev/Laya 的 wire format 一致） |
| FR2 | 可替换的决策引擎：Laya 本地、Jev HTTP、Claude API、Claude Code CLI、规则基线 | `engines/`、`judges.RuleReader` |
| FR3 | 覆盖四个用例：信号判断、风控检查、策略路由、新闻情绪 | `judges.py` 中的 4 个 Judge + `strategies.py` |
| FR4 | 回测：次日开盘成交、手续费和滑点、持仓随价格漂移、支持多空 | `backtest.py` |
| FR5 | 风控：硬约束写在代码里；模型的风控意见**只能减仓** | `risk.py` |
| FR6 | System-1 → System-2 级联：Laya 没把握的样本批量交给 Claude | `engines/cascade.py`、`engines/claude.py` |
| FR7 | 把 Laya 作为 Claude 的工具：MCP server + Claude Code skill | `mcp_server.py`、`.mcp.json`、`.claude/skills/laya-triage` |
| FR8 | 可复现的实验与报告：延迟、读数能力、新闻准确率与校准、合成市场、真实市场 | `experiments/e1…e5`、`reports/` |

## 4. 非功能需求

| 编号 | 要求 | 做法 |
|---|---|---|
| NFR1 | **不能有前视偏差** | 收盘决策、次日开盘成交；判断只用截至当天收盘的特征；有测试专门验证"偷看明天"的策略不会得利 |
| NFR2 | **公平对比** | 规则基线和模型回答同一套问题；阈值只在开发集（合成 seed 0、训练集）上选；验证集和真实市场只用来评估 |
| NFR3 | 可复现 | 合成数据固定 seed；所有模型调用按内容哈希缓存（记录原始延迟和成本） |
| NFR4 | 离线可测 | 单元测试全部跑在合成数据和假引擎上，不需要下载模型，也不需要联网 |
| NFR5 | 成本和延迟透明 | 每个 `Decision` 都带 `latency_ms`、`cost_usd`、`usage` |
| NFR6 | 安全 | 只做研究和模拟：没有券商接口，不下单，输出不构成投资建议 |
| NFR7 | 数据许可 | 行情（Yahoo）和推文数据运行时下载，**不提交进仓库** |

## 5. 不做什么

- **实盘交易和券商对接**：风险和责任都不在研究项目的范围内。
- **高频交易**：实测延迟是几十到几百毫秒（见 E1），离微秒级差了几个数量级。
- **训练或微调 Laya**：官方微调需要 2×T4 跑 4～5 小时。这里只做事后校准（温度 + 偏置）。
- **因子挖掘、定价、协整等数学建模**：这些本来就应该用代码做，不需要"判断模型"。

## 6. 验收标准

1. 用户原始说法里的每一条，都有来源核实或实验结论（见 02 和 04）。
2. 同一策略代码可以在 Laya、规则、Claude 和级联引擎之间切换，只需改一行。
3. `pytest` 全部通过；另有一个可选测试，用真实 Laya 权重验证批量前向和官方单条调用结果一致。
4. 实验报告给出正面和负面的结果，不挑有利的说。
